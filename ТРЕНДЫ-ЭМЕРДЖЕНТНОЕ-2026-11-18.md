## 2. Расписания и самозаживление

**Мир:** cron-воркфлоу — норма ночных осмотров, но расписания **умирают тихо**
(отключаются после 60 дней без активности репо) — нужны внешние пинки и контроль
пульса ([devactivity — почему scheduled workflows исчезают](https://devactivity.com/posts/productivity-tips/github-actions-scheduled-workflows-vanishing-strategies-for-reliable-automation)).

**Дом уже:** Доктор гейтов (одна машина, две двери, честный красный), Дозион с
`dosezor/heartbeat.json`, протокол A-HUSH «тревога однажды».

**Эмерджентное:** у дома два класса машин — лечить инфраструктуру (Доктор: реран
транзиентов) и смотреть флаги (Дозион). Между ними была пустая клетка: **класс машин
по здоровью содержимого** — контент может быть болен при всех зелёных гейтах. Введена
третья машина «Доктор полотен» (T26) с двумя дверями по тому же стандарту: гейт на
push + дозор флота по расписанию; самолекарь лечит тела через API, а не только
гейтит. Хвост: дозор Дозиона сам может стать тихим мертвецом — рекомендация следующей
волне: аларм-однажды, если `dosezor/heartbeat.json` старше 14 дней.

## 4. Личность файла и цепочка поставок

**Мир:** MITRE D3-FMBV — проверка магии байтов как формальная техника
([d3fend.mitre.org](https://d3fend.mitre.org/technique/d3f:FileMagicByteVerification));
OpenSSF Scorecard — пин actions по SHA, branch protection, token permissions
([scorecard.dev](https://scorecard.dev)).

**Дом уже:** scorecard-analysis + zizmor в гейтах, T24-пин-дозор у Дозиона
(`uses:` без SHA = наблюдение), checkout запинен по SHA во всех воркфлоу.

**Эмерджентное:** сходимость полная — T26 становится **зубом по классу**: личность
полотна смотрится магией в трёх местах сразу (гейт `--check`, дежурный обход,
самолекарь флота), а не одним скриптом. Плюс правило живописца в СВОД п.6: запись
без последующей проверки личности = незавершённый статус (У-2.2).
