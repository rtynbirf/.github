# META-AUDIT CHECKLIST — для внешнего AI

> Кто аудитирует правила? Этот чеклист — для внешнего AI (другая модель, другой контекст), который аудирует не код и не репо, а **правила дома**.

## Принцип

Вывод 5 из 22-реестра: «Verifier, написанный проверяемым, всегда даёт fails=0.» Правила дома написаны Хозяином и Z.ai. Кто проверяет правила?

## Что аудитор проверяет

### 1. Consistency
- УСТАВ-ДОМА ↔ AGENTS.md ↔ КАНОН-ПРОВЕРКИ-CLAIMS — не противоречат?
- 22-реестр (архивный) ↔ ЛЕТОПИСЬ (активная) — не дублируют с расхождениями?
- Инварианты I1–I7 (khozyain README) ↔ I-1–I-6 (УСТАВ-ДОМА) — какие действующие?

### 2. Enforceability
- Каждое правило — machine-enforced или human-declared?
- Behavioral rules (I5, I7, Step 0) — теперь enforced? (Step 0 gate создан)
- Что осталось human-declared? (meta-audit сам — human-declared)

### 3. Following
- Последние 10 коммитов — следуют ли правилам AGENTS.md?
- Commit format: `тип(область): суть` — соблюдается?
- Step 0 gate: запускался ли перед операциями?
- Косяки записаны в ЛЕТОПИСЬ тем же тактом?

### 4. Completeness
- Что PASS не доказывает — задокументировано? (КАНОН §«Что PASS не доказывает»)
- Границы инструмента — честно объявлены? (lex-naturae README, HUMAN-LFS README)
- UNKNOWN статус — используется, или всё «наверное PASS»?

### 5. Meta
- Кто аудитирует аудитора? (Этот чеклист — кто его проверяет?)
- Храповик: последний косяк в реестре — когда? Если > 1 недели — система не ловит?
- Proactive fuzz: проводился ли? Когда последний?

## Формат отчёта

Аудитор пишет:
- Consistency: PASS/FAIL/UNKNOWN + конкретные расхождения
- Enforceability: список human-declared правил (risk inventory)
- Following: % коммитов в формате, % операций с Step 0
- Completeness: список незадокументированных границ
- Meta: кто следующий аудитор?

## Важно

**Это не проверка кода.** Это проверка правил. Код может быть идеальным, а правила — противоречивыми, нефorcible, или неfollowed.
