# ПРОТОКОЛ СВЕРКИ СПЕЦИФИКАЦИИ С КОДОМ

> Мандат Хозяина 2026-11-15: «ТЕПЕРЬ ЭТУ ЖЕ ПРОЦЕДУРУ ПО ВСЕМ РЕПОЗИТОРИЯМ СДЕЛАЙ И НАПИШИ ДРУГИМ АГЕНТАМ, ЧТОБ ВЫПОЛНЯЛИ ЭТУ ПРОЦЕДУРУ»

## Цель

Каждый репозиторий аккаунта `rtynbirf`, имеющий спецификацию (конституцию, доктрину, 
канон, устав, инварианты), проходит сверку: **каждая статья/инвариант/закон имеет 
точку принуждения** в коде/CI/скрипте/тесте и **проверяется исполнимым тестом**. 
Незакрытые вопросы — видимы, не спрятаны («пусть просто живут» = ловушка M4 наизнанку).

## Процедура (для любого агента на любом репо)

### Шаг 1: Найти спецификацию
- README.md, CONSTITUTION.md, УСТАВ.md, КАНОН.md, doctrine/, docs/, ZAKON_DOMA.md
- Извлечь нумерованные статьи/инварианты/законы/гарантии

### Шаг 2: Для каждой статьи — найти точку принуждения
- **Код:** функция/метод/класс, где статья реализована
- **CI:** воркфлоу, который проверяет статью
- **Скрипт:** инструмент, который сверяет статью (например, khozyain_sweep.py)
- **Тест:** unittest/pytest, который проверяет статью

### Шаг 3: Написать верификацию
- Для каждой статьи: тест/эксперимент, который проверяет точку принуждения
- Формат результата:
  - **PASS** — полностью реализована и проверена
  - **PARTIAL** — реализована частично; указать что нужно для полного (обычно R-этап)
  - **FAIL** — не реализована; gap

### Шаг 4: Запустить и записать
- Прогнать верификацию
- Результаты — в репо (эксперимент или docs/AUDIT-*.md)
- Запись в `.github/docs/ЛЕТОПИСЬ-ФАКТОВ.md` (A-NN)
- Коммит в формате `тип(область): суть`; без force-push

### Шаг 5: Запушить
- Обычный `git push`; при reject — `git pull --rebase` сначала
- Косяки сессии — в ЛЕТОПИСЬ (класс Е)

| khozyain | УСТАВ-ДОМА, I1–I7 | 7 | 4 PASS + 3 PARTIAL | khozyain/docs/AUDIT-I1-I7.md |

## Что даёт

- **Каждой статье — конкретный статус.** Не «наверное реализовано», а PASS/PARTIAL/FAIL 
  с точкой принуждения.
- **PARTIAL — честная граница.** Указывает, какой R-этап (R1/R2/R3…) закроет полное 
  соответствие. Не gap, а roadmap.
- **Вопросы закрыты для тех, кто придёт после.** Не «пусть просто живут» с 
  незакрытыми утверждениями — а видимый ответ по каждой статье.

## Обязательство агента

Агент, входящий в репо со спецификацией и не имеющий AUDIT-*.md — **первым делом 
проводит сверку** по этому протоколу. Это Step 0 для репо со спецификацией, 
как чтение 22-реестра — Step 0 для аккаунта.
