# СТАНДАРТ ДОМА · Доктор полотен · «полотно = байты» (T26, волна РЕВО 2026-11-18)

> Издан волной РЕВО 2026-11-18 по делу «ССЫЛКИ БИТЫЕ» (42 полотна на 42 телах):
> картины профиля и всех живых репо были base64-текстом вместо байтов при живых
> URL и зелёных гейтах. Канон аккаунта: AGENTS.md этого хаба; приёмка — только
> машинная (магия байтов / HTTP / SHA). Числа — из живых проб, никогда руками.

## 1. КЛАСС БОЛЕЗНИ T26 (текст-вместо-байтов)

- Живописец-агент кладёт в contents API **строку base64** вместо **байтов** полотна
  (у баннеров — дважды закодированную: base64×2). Полотно в git — ASCII-текст 77–190 КБ
  с чужим расширением `.png`.
- raw.githubusercontent отдаёт `Content-Type: text/plain` + `X-Content-Type-Options:
  nosniff` — браузер **обязан** отказаться рисовать текст как изображение. Результат:
  картинка битая **у всех посетителей, всегда** — при живых ссылках и зелёных гейтах.
- Почему прошли все стражи: дежурный обход мерил баннер **размером** (≥20 КБ), а больное
  полотно — крупный текст; Доктор гейтов лечит транзиенты инфраструктуры; Дозион —
  флаги репо. **Личность полотна до этой волны не смотрел никто.**
- Противоядие по канону: MITRE D3-FMBV «File Magic Byte Verification» — личность файла
  определяется магией байтов (`\x89PNG`, `\xff\xd8\xff`, `GIF8`, `<svg`, `RIFF·WEBP`).

## 2. ОДНА МАШИНА (`tools/paint_doctor.py`, три режима)

- `--check` — гейт cwd: каждое полотно обязано быть байтами своего формата; больное —
  список и честный exit 1 (ничего не лечит — красный не подмазывается, N-10).
- `--local-heal` — лекарь cwd: декодировать больные (до base64×3) в настоящие байты
  на диске; коммит делает машина за ним (зуб A-HUSH, 3 попытки против гонки за main).
- `--heal` — самолекарь флота: обходит живые тела владельца через API, декодирует и
  записывает полотна коммитом «доктор полотен: base64-текст → настоящие байты (T26)»;
  архив (только чтение) и отказ API — честный пропуск; дедлайн дозора 8 минут; тишина I0.
- stdlib-only, живёт в публичном .github — биллинг-иммунитет (канон дозора).

## 3. ДВЕ ДВЕРИ (workflow «Доктор полотен», машина одна)

| Дверь | Триггер | Что делает |
|---|---|---|
| СОБЫТИЕ | `push` в main | гейт `--check`; красный → `--local-heal` + коммит (3 попытки); не спасло — честный красный |
| ДОЗОР | `schedule` (еженедельно) + `workflow_dispatch` | `--heal` по всему флоту, свод в GITHUB_STEP_SUMMARY |
| (ручная) | `workflow_dispatch` | обе двери сразу: гейт тела + дозор флота |

- Доктор доктора запрещён: этот воркфлоу не реранит себя и не смотрится Доктором гейтов
  (имя «Доктор полотен» вписано в список СОБЫТИЕ-двери Доктора гейтов сменой ритуала —
  коммитом, по §2–3 того стандарта).

## 4. ЧТО ОБЯЗАН СДЕЛАТЬ ЖИВОПИСЕЦ (СВОД ОФОРМЛЕНИЯ п.6)

1. В contents API кладётся `content = base64(БАЙТЫ)`. Если твой «файл» уже base64-строка —
   ты закодировал дважды: почини источник записи, а не полотно.
2. После записи полотна — проверка личности: `python3 tools/paint_doctor.py --check`.
   «Записал» ≠ «полотно живо»: по У-2/П3 артефакт = его байты, заявление без артефакта
   не учитывается.
3. Динамические полотна дома (музы, паспорта) — текстовые SVG по своей природе: их
   личность проверяется началом `<svg` — дежурный обход смотрит её с этой волны.
